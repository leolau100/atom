大家好，我是aric。

一个工业数据采集项目，如果只负责把 PLC 数据读出来，离真正的监控软件还差不少东西。

IndustrialDAQ 把这部分工作往前推进了一步。它基于 .NET 8、WPF 和 Prism 开发，除了设备采集，还集成了实时趋势、历史数据、规则计算、报警管理和权限控制。

对于想用 C# 开发工业监控软件的人来说，这个项目值得研究。

不只是读取 PLC 数据

IndustrialDAQ 采用插件式驱动架构，目前仓库包含 Modbus TCP、OPC UA、S7 和 MQTT 驱动。

设备、驱动参数和数据点通过 JSON 配置管理，部分配置支持热加载。需要调整设备或测点时，不必把所有信息都写死在代码里。

这套设计比较适合二次开发。后续要增加新的设备类型，可以沿着现有驱动架构扩展，而不是把通信逻辑全部塞进主程序。

当然，支持某种协议不等于兼容所有品牌和型号的设备，实际使用前仍需要验证驱动能力。

采集到的数据，可以直接做趋势监控

项目提供了实时趋势和历史趋势功能。

用户可以选择设备下的数值型数据点，观察数据实时变化，也可以查询指定时间范围内的历史记录。

趋势界面还支持十字线查看和报警点标识，方便定位异常发生的时间。

对于正在开发 HMI 或 SCADA 的工程师，这部分比单独研究一个通信库更有参考价值。它涉及的不只是数据读取，还包括数据点管理、趋势数据服务和历史数据存储。

报警、计算规则也集成进来了

IndustrialDAQ 支持计算规则，可以通过表达式处理已有数据点，并生成虚拟数据点。

例如，将采集到的温度、压力或其他参数进行计算，再把结果提供给趋势展示或后续业务使用。

报警模块则覆盖报警触发、恢复、确认和历史记录等环节，相关规则支持动态加载。

报警信息还可以通过钉钉、企业微信兼容的文本 Webhook 适配器向外发送。

这些功能组合起来，已经不只是一个简单的 PLC 通信测试工具，而是具备了工业监控应用的一些基础模块。

权限管理也考虑到了

项目提供了用户、角色和动态授权机制。

权限判断可以关联具体资源和操作，并采用默认拒绝、拒绝优先的策略。

比如，某个操作员可以查看数据，但不一定拥有修改设备参数的权限。

系统还会记录登录失败、权限变更、授权拒绝和数据点写入结果等审计事件。对于需要区分操作权限、追踪关键操作的工业软件，这部分设计值得关注。

甚至还加入了机器视觉

IndustrialDAQ 还有一个比较特别的模块：机器视觉。

目前仓库提供的是瓶盖有无检测 MVP，包含模拟相机、ROI 模板教学、NG 图片保存，以及与数据点和报警的联动。

这更适合作为功能验证和二次开发的参考，不能直接等同于成熟的工业视觉检测系统。

如果你正在研究如何把视觉检测结果接入现有的设备监控和报警流程，可以重点看看这部分实现。

用什么技术开发？

项目采用 .NET 8 和 WPF，界面使用 Prism MVVM 架构，图表基于 LiveChartsCore。

存储方面支持 SQLite 和 PostgreSQL，日志使用 Serilog。

仓库还提供了 Python 编写的 Modbus TCP 模拟设备脚本，可以先在没有真实 PLC 的情况下测试采集、参数写入和报警流程。

需要注意的是，它属于 Windows 桌面应用，不是直接部署到服务器上的 Web 管理平台。使用前需要准备相应的 Windows 和 .NET 开发运行环境。

这个项目适合谁？

如果你正在使用 C# 开发工业监控软件，可以研究它的驱动插件、数据点模型、趋势服务、报警状态机和动态权限设计。

如果你想找一个现成的工业数据采集软件直接投入生产，则需要进一步验证目标设备兼容性、长期运行稳定性和现场部署要求。

大家好，我是DoublePoint。

做工业数据采集，如果项目本身就是用 Python 开发的，遇到一台提供 OPC UA 服务的设备，其实可以直接用 Python 读取数据，不一定非要再搭一个 Java 或 C# 网关。

比如，包装机上的温度、转速、报警状态和累计产量，都可以通过 OPC UA 暴露出来。拿到这些数据后，再用 pandas 做清洗和统计，或者存进时序数据库，后面的工作就能沿用原来的开发环境。

FreeOpcUa 开源组织的 python-opcua，就是用来做这件事的。

它能做什么？

python-opcua 是一个 OPC UA 客户端和服务端库。

客户端可以连接设备或上位系统提供的 OPC UA Server，浏览地址空间、读取和写入变量、订阅数据变化，还支持事件、方法调用、历史数据读取，以及证书和加密通信。

服务端也可以自己搭建。创建对象、添加变量、发布数据，甚至模拟一台设备，都能通过代码完成。

对于工业数据采集项目，这意味着两件事：有真实设备时，可以直接连接读取数据；没有设备时，可以先搭一个模拟服务端，让客户端和上层系统完成联调。

需要注意，它连接的是提供 OPC UA 服务的设备或系统，并不是所有 PLC 都能直接连接。设备是否支持 OPC UA、开放了哪些节点，需要提前确认。

几个比较实用的功能

1. 直接采集设备数据

如果数据分析、清洗和可视化已经使用 Python，就可以在同一个程序里完成 OPC UA 采集和后续处理，省去额外开发数据转发接口的工作。

2. 订阅数据变化

除了主动读取变量，还可以订阅节点变化。温度、压力、转速和报警状态等数据，都可以通过订阅机制获取更新。实际采集效果还要看设备能力、服务端配置和网络情况。

3. 模拟设备，方便开发联调

开发采集程序时，现场设备不一定随时能用。可以自己创建对象和变量，让上位机、MES 或 SCADA 连接模拟服务端，提前验证读取、订阅等功能，不必一直等现场设备。

4. 使用命令行工具排查节点

项目还提供了浏览节点、读取变量、写入变量、调用方法和订阅数据等命令行工具。现场排查时，想确认某个节点是否存在、当前值是多少，可以先用工具检查，不必每次都写测试程序。

5. 部署到边缘设备

Python 程序也可以部署到树莓派等边缘设备上。不过，节点数量、采集频率和内存占用都需要实际测试，不能仅凭库本身支持 OPC UA，就认定它适合所有边缘场景。

快速上手：读取一个节点

旧版 python-opcua 的安装包名称是 opcua，可以通过 pip 安装：

pip install opcua

下面是一个最基本的客户端示例：

from opcua import Client client = Client("opc.tcp://localhost:4840/freeopcua/server/") try: client.connect() root = client.get_root_node() print(root.get_browse_name()) # 按 NodeId 获取节点并读取当前值 var = client.get_node("ns=2;i=2") print(var.get_value()) finally: client.disconnect()

示例中的地址是本机 OPC UA 服务端地址，NodeId 也需要根据实际服务端的地址空间修改。连接现场设备时，应使用设备提供的 endpoint 和对应节点标识。

自己搭建一个模拟服务端

除了读取数据，也可以用它发布变量，让其他客户端来读取。

from opcua import Server import time server = Server() server.set_endpoint( "opc.tcp://0.0.0.0:4840/freeopcua/server/" ) uri = "http://freeopcua.github.io" idx = server.register_namespace(uri) objects = server.get_objects_node() myobj = objects.add_object(idx, "MyObject") myvar = myobj.add_variable(idx, "MyVariable", 6.7) myvar.set_writable() server.start() try: while True: time.sleep(1) finally: server.stop()

运行后，服务端会创建一个对象和变量，客户端可以读取变量值。调用 set_writable() 后，客户端还可以尝试写入该变量。

这段代码适合做功能验证和模拟测试。真正部署到生产环境时，还需要配置合适的安全策略、访问权限和证书，不能直接把测试服务暴露到不可信网络。

选型时要注意：同步版已经停止积极维护

这一点在选型时不能忽略。

python-opcua 仓库已经明确标记为 deprecated，官方建议新项目转向 opcua-asyncio，也就是通常所说的 asyncua。

两者的 API 有不少相似之处。旧版使用同步调用，新版主要使用 asyncio 异步调用。例如，读取节点值时，异步版本需要使用 await：

# python-opcua from opcua import Client client = Client(url) client.connect() try: value = client.get_node(nodeid).get_value() finally: client.disconnect()
# asyncua from asyncua import Client async def main(): client = Client(url) await client.connect() try: value = await client.get_node(nodeid).get_value() finally: await client.disconnect()

迁移时不能简单地给所有方法加上 await，还需要根据实际 API 和程序结构调整。如果现在准备启动新项目，建议优先评估 asyncua；已有的 python-opcua 项目，则可以根据维护成本决定是否迁移。

大家好，我是aric。

做工控的都懂，网关、组态、上位机画面，向来是三摊事。网关管采集，组态软件管画面，HMI 再单独一套。真要自己攒一套能跑的生产系统，光把这些拼起来就够喝一壶。

有个用 C# 写的开源项目，思路很直接：一个项目，把轻量级工控网关、数据采集归档、报警配置，连同人机界面（HMI）的设计器和运行器，全塞进去了。不绕弯子，一个工程里能跑通从下位机到画面的整条链路。

举个最朴素的例子：一个小水厂想把几台泵、几个液位和阀门的实时状态搬上屏幕，又不想一上来就上一套动辄几万、还得专门配工程师的商业组态软件。这类需求，它刚好对得上——轻、能跑、协议够用。

图：运行时 HMI 监控画面。深底色的工艺流程图，管路、塔器、阀门和状态标签实时刷新，哪个设备异常一眼就能看出来。
先说它最实在的地方——画面。它自带一套图元系统，阀门、电机、料仓、输送线这些工业常用元件都是现成的，拖到画布上就能摆。

图：图元设计器。左侧资源树里挂满了现成的设备图元——阀门、电机、料仓、输送线……拖到画布上就能组态；右侧还能看到每个图元的属性。
设计态和运状态是分开的。设计时用 Visual Studio 加一个设计器插件，画好流程图、连好线、绑好变量；运行时编译成可执行文件，现场直接开。

图：组态设计态。画布上摆好设备图形后，用「标题绑定」窗口把画面元素和变量关联起来，运行时才会跟着数据动。

图：设备图形本身是矢量绘制的，选中后会带编辑手柄，位置和连线都能自由调整，不是死的方块。
图元不是死的。每个元件都能继承一个基类、写一点点代码扩展，所以你能做出贴合自己工艺的图形，而不是被一堆方块将就。

数据采集这块，它支持实时采集、历史归档和变量触发报警。变量不是散着管的，有专门的变量管理器统一维护。实时数据先进内存缓存，只有变化了才推给客户端，省了不少无效轮询。

图：变量管理器。标签名、地址、数据类型、是否报警、是否归档集中维护，还能把驱动 dll 注册进来、整体导入导出；状态栏显示当前标签数 122。
单个变量在这里配：名字、数据类型（开关型、整型、浮点）、寄存器地址、默认值，还有归档周期。改完一批变量，可以整体导入导出。

图：单个变量设置窗口。变量名、数据类型（开关型 / 整型 / 浮点）、寄存器地址、默认值，以及归档周期（图里是 100）都在这里配。
协议层是它另一个重点。已经发布的驱动覆盖内存数据库、Modbus TCP/RTU、OPC DA、西门子 S7-200/300/1200/1500、松下、AB EtherNetIP、欧姆龙 UDP；作者还列了后续要补的 DDE、三菱。换句话，现场常见的那几种 PLC 和总线，基本都能接。

驱动这块的设计也干净：网关下挂驱动、驱动下分组、组下才是具体变量，层级很清楚。要接一种新 PLC，照着接口写个驱动 dll 注册进来就行，不用改核心。

图：驱动参数设置。类型下拉里直接选 S7 以太网、Modbus RTU/TCP、OPC、SQL 等协议，再填服务器和超时就能用。

图：已加载的驱动一览。Modbus RTU、Modbus TCP、S7 以太网、OPC、SQL 数据库……支持哪些协议，表里列得清清楚楚。
加新协议也不麻烦。把驱动 dll 指过去，勾选要注册的组件，点一下注册就生效。

图：新增协议驱动时，先指到 dll 所在目录，勾选要注册的组件（比如 SiemensTCPIP / S7 以太网协议），点一下注册就生效。
画面上的图形要动起来，得把图元和变量绑上。标签绑定窗口干的就是这个：左边选设备（电机、风机、旋风分离器），右边填对应的变量名，运行时数值和报警就跟着走了。

绑定变量时有个细节很实用：报警、运行、设备名这些状态可以分别映射到不同图元属性，所以同一个电机在画面上能同时显示名字、转 / 停、还有报警闪红。

图：标签绑定窗口。把画面上的电机、风机、旋风分离器直接映射到具体变量，左侧属性列和右侧标签文本一一对应。
数据采回来不是只看着。历史趋势图能按时间段回放，电流、输出频率、母管压力、阀门开度、蒸汽温度，曲线一起铺开，还能开十字光标读具体数值。做工艺分析、查异常，这张图够用。

归档策略也实在：历史数据既能写进 SQL 的归档表，也能按天转储成二进制文件。点多了之后，二进制文件顶着，数据库不被拖垮。比如一个水箱液位越过上限，变量管理器立刻标红、触发报警，同时把这次变化写进历史，不用你一直盯着屏幕。

图：历史趋势图。选好起止时间，电流、输出频率、母管压力、阀门开度、蒸汽温度等曲线一起回放，还能开十字光标读数。
环境上得说清楚：它跑在 Windows 上，依赖 .NET Framework 和 SQL Server（Express 也行），官方给的示例是 Win7/8/10/Server 2008 配 .NET 4.x。也就是说，它更偏一套能落地的 Windows 工控套件，不是跨平台的云原生那一路。想自己扩驱动，Visual Studio 新建个类库工程就能动手。上手也不算重：官方给了示例库和配置文件，还原数据库、改两行网关地址就能把 DEMO 跑起来，门槛主要在 Windows 加 VS 这套环境本身。

所以它特别适合几类人：小水厂 / 供热站想做个本地监控大屏的；设备厂商要给自家机器配一套演示画面的；还有想搞明白一套 SCADA 到底怎么搭的开发者。预算紧、机器不多、就在 Windows 上跑，它就很顺手。

图：想自己加驱动也很直接。用 Visual Studio 新建一个类库工程，目标框架选 .NET Core 2.0 就能动手改。
顺带提一嘴，作者一直在往 .NET Core 上搬，想让它脱离 Windows 跑起来。目前网关部分已经有测试版，但人机界面那块受限于 WPF 没进 Core，短期还得留在 Windows。所以现在用，心态放平：把它当一套成熟好用的 Windows 端工控组态工具，别指望它去 Linux 上顶替一切。

一句话：它是那种「能直接拿去用、也能拆开学」的项目，不玄乎，胜在把 SCADA 该有的几块一锅炖了。

要是哪天你接了个本地监控的小活儿，机器不多、又不想上一整套商业组态软件，它大概率就是那个不用大动干戈就能交差的选择。

协议

仓库 LICENSE 是 LGPL。

这协议比 GPL 温和。简单说：你可以把它用在自己的项目里，包括商业场景；动态链接或者当作库调用，改不改源码都行。但有一点要记住——如果你改了它本身的库代码，这部分改动得开源回去，不能闷声闭源。界面、业务系统这些自己写的部分，不受影响。

所以它适合两类人：一是想快速搭一套 Windows 端监控 / 组态系统的团队，直接拿来用、按 LGPL 走；二是想学 SCADA 架构、自己照着改驱动的开发者，协议不卡你。只是别把它当「完全无约束的免费库」——改了核心再分发，开源义务还在。

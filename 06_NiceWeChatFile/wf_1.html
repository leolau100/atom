三万一千多颗星，榜首是一块几十块的 ESP32 板子：接上麦克风、喇叭、小屏就能对话，还能关灯、拉窗帘。

它叫小智，C++ 固件，端轻云重。

图：MCP 是云端大模型与设备控制之间的桥梁。

它火，是因为承认芯片弱。

ESP32 主频、内存、算力只是微控制器级别，本地跑不动大语言模型。

硬件接线、固件源码、通信协议、服务端实现，整条链路一样不藏。

三段链路

端侧：麦克风采声，本地离线唤醒，音频编码成 Opus 流送出。

云侧：流式跑「语音转文字—大模型生成—文字转语音」，也支持端到端实时语音模型。

回到端侧：音频回传，功放加喇叭播出，屏幕同步跳表情、状态、字幕。

带回声消除的板子能全双工，说到一半打断，它会停下来接着听。

图：一体化成品板，开机配网即用。

联网给得宽：Wi-Fi、以太网、USB 网卡、Cat.1 走 4G，部分硬件可在无线与蜂窝间切换。

硬件门槛

最低 BOM：ESP32 板、数字麦克风、功放加喇叭、可选屏、按键、锂电池、杜邦线。

图：面包板原型，麦克风、小屏、喇叭靠杜邦线连起来。

芯片覆盖 ESP32、C3、C5、C6、S3、P4，整套成本几十元到一百多元。

从听见到认人

离线唤醒不依赖网络，唤醒词可自定义，字体、表情、聊天背景可在网页端改。

声纹识别分辨说话的是谁，给不同人不同称呼。

图：彩屏成品，屏幕除字幕外还承担表情与状态表达。

能力被整理成可配置固件能力集，换块板子挑对应配置，能力大体还在。

MCP：从能聊天到能动手

没有 MCP，天花板是一台问答机：大模型输出文字，文字和 GPIO 电平隔着鸿沟。

MCP 把工具统一描述给大模型：名称、功能、参数、返回值，由模型判断调哪个、传什么。

文字和动作之间的鸿沟，被一套协议填平。

设备端 MCP 注册音量、舵机、GPIO、屏幕；「把灯调成暖色」落到板子是几路 PWM 占空比改变。

云端 MCP 接入智能家居、桌面操作、知识检索、邮件收发，设备只当入口。

图：小型化成品，MCP 硬件载体可以挂在身上。

设备控制从预设状态机变成模型自主编排，终端成了大模型能临时调度的物理节点。

生态与可玩性

固件矩阵覆盖上百个板卡目录、上百个发布变体，从方形屏、圆形屏到四足机器狗。

通信侧两套协议都有公开文档：WebSocket，和 MQTT 加 UDP。

图：带触控屏的开发板，底下仍是同一套开源固件。

模型后端没锁死：默认连官方服务，注册后免费用实时语音模型；控制台可换配置，社区有自建服务端，数据能留在局域网。

图：上百个板卡目录，手头那块板大概率有人趟过坑。

榜首：三层开放

硬件开放：接线、物料、板级适配摊开，可复刻也可自己画板。

固件开放：以宽松许可证发布，允许自由使用、修改乃至商用。

协议开放：通信协议有文档，服务端可替换。

图：同一套固件跑在四足机器狗上。

语音进来、模型决策、舵机动作、表情反馈，感知—决策—执行闭环不用昂贵算力就能跑通。

冷静的边界

最根本的是依赖云端：断网后本地只剩离线唤醒，没有大模型推理。

级联式「识别—思考—合成」延迟客观存在；麦克风、回声消除、腔体决定远场唤醒率。

几十块物料在安静书桌上不错，放进嘈杂客厅容易露怯，不同板子口碑差很多。

图：圆形屏异形设备同样收进支持矩阵。

工程化还在：量产一致性、功耗续航、射频与安规认证、售后 OTA、儿童场景合规。

大家好，我是aric。

让 AI 画一张架构图，回来的往往是一排圆角矩形加默认配色，和文档里其他部分的风格对不上。要么自己打开 Figma 画半小时，要么干脆不放图。经常写技术博客、做分享材料的人，多半卡在过这一步。

先说清楚它是什么。Agent Skill 是写给 AI 编程助手的一套规范文件：装进 Claude Code、Codex、GitHub Copilot、Cursor 这类宿主后，遇到画图需求，Agent 会按规范里的规则执行。diagram-design 就是这样一个技能包，产出一个自包含的 HTML + SVG 文件，双击就能在浏览器里打开。项目 2026 年 4 月开源，MIT 许可，目前 5.8 万 Star，最近几天仍有代码推送。

这篇文章说清四件事：它提供什么、图为什么好看、实际怎么用、有哪些限制。

它解决什么问题？

AI 画图的问题通常不在内容。让 Agent 画一个"前端、后端、数据库、Redis 缓存"的架构图，该有的节点它都画得出来，缺的是品味：默认的圆角盒、默认的主题色、莫名其妙的阴影，放在哪篇文档里都长得一样。

作者 Cathryn Lavery 在 README 里写得很直白：模型已经理解了内容，缺的是品味，所以她把品味写成了文件。一个强调色只留给最该看的一两个元素，1px 细线，不用阴影，所有坐标落在 4px 网格上。

这个项目的产出物是一个 .html 文件，图表以内联 SVG 形式嵌在里面。普通输出没有构建步骤，没有 JavaScript，没有外部图片依赖；默认情况下唯一的网络请求是 Google Fonts，换成系统字体后完全离线可用。

它和 Mermaid 不是二选一的关系。Mermaid 的图是文本，能 diff，GitHub 直接渲染，适合活在 Git 里、每个 sprint 都变的文档图；diagram-design 面向准备发布的那张图，比如博客配图、演讲幻灯片、官网文档。

下文配图全部取自仓库 skills/diagram-design/assets/ 下的示例文件，由我本地栅格化渲染，字体效果与在浏览器中打开略有差异。

核心能力

45 种图示类型，每种三个静态变体

工程图这边有架构图、架构对比图、IT 现状图、部署图、时序图、状态机、ER 模型、UML 类图、数据库模式；流程图、泳道图、用户旅程图、看板覆盖流程与协作；条形图、甘特图、散点图、桑基图、热力图、雷达图、四象限图覆盖数据呈现；树形图、嵌套图、组织架构图、分层图、爆炸分解图、轴测平面图覆盖结构与空间。总共 45 种。

每种类型带三个静态变体：minimal light、minimal dark 和 full-editorial，后者带摘要卡片，适合整页展示。仓库 assets 目录下有每种类型的示例 HTML，本地打开就能逐个翻；也可以直接逛线上画廊。

类型参考文件按需加载：画流程图只读 type-flowchart.md，画架构图只读 type-architecture.md。新增类型不影响其他文件，Agent 的工作上下文也保持紧凑。

一套写死的设计系统

好看不是随机的，是规则：

一个强调色（默认 #bf4520），每张图只标出 1 到 2 个焦点；

1px 细边框，不用阴影，圆角最大 10px；

所有坐标、宽度、间隙都是 4 的倍数；

三套字体：Instrument Serif 做标题和斜体批注，Geist 做节点名，Geist Mono 做端口、URL、字段类型这类技术子标签。

对比度有硬门槛。CI 里跑 WCAG 检查，文字角色在浅色和深色纸面上都要过 4.5:1，默认皮肤的强调色文字实测 4.71:1。这些规则有 CI 兜底：每个 Pull Request 在 Linux、Windows、macOS 三端跑皮肤检查、渲染检查和几何校验。

品牌 onboarding：让图匹配你的网站

默认皮肤是 jet-black 加橘色。想换成自己品牌的配色，不用手改文件，对 Agent 说一句话就行：

onboard diagram-design to https://yoursite.com

Agent 会抓取首页，提取主色和字体栈，映射到语义角色（paper、ink、muted、accent、link），展示一份 diff，确认后写入 references/style-guide.md。之后每张新图都用这套 token：网站的背景色成为图的纸色，CTA 颜色成为焦点强调色。

多客户并行有 profile 机制：品牌配置存成命名文件，项目里放一个 .diagram-design 标记指向它，几个工作区互不覆盖。另外，首次在新项目里画图时，如果风格指南还是默认值，skill 会停下来问你要不要先跑 onboarding，不会默默把默认皮肤的图塞进你的品牌项目。

导入重绘：draw.io、Mermaid、Excalidraw 都能翻新

手里已有的图不用重画。把源文件指给 skill，它会用同一套设计系统重绘，支持 draw.io（.drawio、.drawio.xml、内嵌图表的 .drawio.png、.drawio.svg）、Mermaid（.mmd、.mermaid 或 Markdown 里的代码块）和 Excalidraw 场景文件（.excalidraw、.excalidraw.json，不含导出图）。

重绘不是一比一转换，四个旋钮决定输出：

格式：html、svg、png、html+png；

尺寸：doc-inline、slide-16x9、social-og、print-a4-landscape 等，投影幻灯片用 16px 节点名而不是 12px；

详略：faithful（最多 24 节点）、balanced（最多 12）、simplified（最多 7），按固定阶梯降级；

受众：engineer、mixed、executive，改的是措辞。Auth Service / JWT · RS256 · :8443 给工程师看，Sign-in 给高管看。

每次导入结束附一份 fidelity ledger，列出哪些节点被合并、折叠、丢弃：

Detail: balanced · 12 source nodes → 8 drawn Collapsed: "Token valid?" decision → edge label on Gateway → Auth Dropped: 1 sticky note ("legacy path, to be retired"), unconnected in source Kept in full: the request path (Web/Mobile → Gateway → Orders → Postgres)

源文件你最熟，少了什么一眼能看出来。

导出 SVG / PNG，接住下游工具

图默认是 HTML，也可以只导出图表本身。SVG 会抽取 ＜svg＞ 节点并注入字体，能在 Figma、Illustrator 里直接打开；PNG 通过 Playwright 按 2 倍栅格化，--scale=3 可以更清晰，发幻灯片够用。PNG 导出需要一次性装好 Playwright 和 Chromium。

放到实际场景怎么用？

装好 skill 之后，画图就是一句话的事。最常见的安装方式：

npx skills add cathrynlavery/diagram-design

Claude Code 用户也可以走插件市场，带斜杠命令和自动更新：

/plugin marketplace add cathrynlavery/diagram-design /plugin install diagram-design@diagram-design

然后直接用自然语言提需求，比如给一篇应用架构的博客文章配图：

Make me an architecture diagram of my app: frontend, backend, database, Redis cache.

Agent 先选定类型、说明计划，再写出一个 .html 文件，双击打开即可。对生成结果不放心，仓库带了自检脚本（在克隆的仓库里运行）：

python3 skills/diagram-design/scripts/self_check.py my-diagram.html

打印 OK 表示文件通过单文件安全、无障碍命名等检查，加 --offline 会连 Google Fonts 链接一起查。

同一套规范覆盖的远不止架构图。给团队新人写服务部署说明，可以要一张部署图：

季度规划评审要排优先级、画路线图，四象限图和甘特图也在覆盖范围内：

有什么限制？

README 把自己的局限写得很明白，这里直接转述：

输出质量取决于你用的模型。同一个提示词跑两次，布局可能不一样，想要稳定产出得固定模型和版本自己试。

它不是可编辑的源格式。没有文本可以 diff，也没有画布可以拖框。活在 Git 里、每个 sprint 都改的文档图，Mermaid 仍然是更合适的选择。项目自己的说法是，它服务于"你准备发布的那张图"。

PNG 导出不是零依赖。要走 Playwright 加 Chromium，一次性安装，但完全离线的环境要么放弃 PNG 导出，要么自己搭环境。

默认会加载 Google Fonts。这是图表文件唯一的网络请求；要求完全离线时，需要在风格指南里把字体来源设为 system。

另外它只管画图。数据存储、告警、设备管理这类平台功能不在范围内，仓库里也没有相关代码，别指望一个画图技能包兼任平台。

适合什么团队？

适合的：

经常写博客、文档、周报，需要配图但不想开设计工具的人；

团队有统一视觉规范，希望每张图自动匹配品牌色和字体；

重度使用 Claude Code 等 Agent 工具的开发者，画图是日常工作流的一环。

不太适合的：

图表要进 Git、要 review diff、随文档频繁演进的团队，继续用 Mermaid；

需要交互式画布、拖拽编辑的场景，那是 draw.io、Excalidraw 的地盘；

完全离线且不愿装 Playwright 的环境，PNG 导出会受限。

总结

diagram-design 做了一件很窄的事：把"什么图算好看"翻译成 Agent 能执行的规则。类型选择、4px 网格、配色、字体、对比度，全部写进参考文件，按需取用。它补的不是模型的能力缺口，是品味缺口。

如果你的图最终要出现在别人面前，这个技能值得装上试一次。

大家好，我是aric。

调试 Modbus 设备，最麻烦的往往不是建立连接，而是连接成功之后，怎么确认数据读得对不对。PLC 返回的寄存器值不符合预期，仪表读数不对，或者主站发出了请求却没有得到响应，这时候光看串口是否连通还不够。最好能直接读取寄存器、修改数据，再查看通信报文。

qModMaster 就是为这类工作准备的工具。它是一个基于 Qt 的 Modbus 主站软件，支持 Modbus RTU 和 Modbus TCP，还提供总线监视功能，可以查看通信流量。

一、RTU 和 TCP 都能测

Modbus 现场常见的两种通信方式，qModMaster 都支持。

Modbus RTU： 通过串口与设备通信，适用于 RS-232、RS-485 等串行通信场景。

Modbus TCP： 通过以太网与设备通信，适用于 PLC、网关和仪表等支持 Modbus TCP 的设备。

调试 RTU 时，需要配置串口、波特率、校验方式、数据位和停止位等参数；使用 TCP 时，则需要配置目标设备的 IP 地址和端口。配置好连接后，就可以向 Modbus 从站发送请求，不必专门编写一段测试程序。

二、寄存器读写，是它最实用的功能

qModMaster 可以作为 Modbus 主站，读取或写入从站支持的相应数据区域。

Coil（线圈）：读取或控制单个位状态。

Discrete Input（离散输入）：读取数字量输入状态。

Holding Register（保持寄存器）：读取或修改设备参数、运行数据。

Input Register（输入寄存器）：读取设备提供的输入数据。

具体能否写入，取决于数据类型、设备实现和寄存器权限。比如，离散输入和输入寄存器通常用于读取，不能因为主站软件支持 Modbus，就认为设备上的所有地址都能写。

对于 PLC 工程师来说，这个功能很适合用来验证寄存器映射。例如，程序里配置了一个保持寄存器地址，可以先用 qModMaster 读取对应地址，确认返回值是否符合预期。若设备允许写入，也可以修改测试值，再观察 PLC 程序或设备状态是否发生变化。

如果主站程序读取到的数据不对，这种独立测试也有助于判断问题究竟出在设备、地址配置，还是自己的通信程序上。

三、通信不正常，直接看报文

qModMaster 还带有总线监视功能，可以检查通信流量。README 对这一功能的描述是可以查看总线上的所有通信流量，源码里则有 rawdatamodel、rawdatadelegate 负责原始数据的展示。

这比只看一个“连接成功”或“读取失败”的提示更有用。Modbus 通信异常可能来自多个环节：

请求发出后没有响应；

从站返回异常响应；

功能码或寄存器地址配置不正确；

返回的数据与预期不一致。

查看报文可以进一步确认主站究竟发送了什么、设备返回了什么。对于开发 Modbus 主站程序、排查仪表通信问题的人来说，这个功能值得关注。

不过，报文监视主要解决通信层面的排查问题。至于一个寄存器的数值应该如何解释，例如两个寄存器组合成浮点数、字节序如何排列，仍然需要结合设备手册判断。

四、适合哪些场景？

PLC 与仪表联调： 检查设备是否正常响应，验证寄存器地址和数据读写。

Modbus 主站开发： 在开发自己的采集程序之前，先用独立工具确认从站的通信行为。

现场故障排查： 通过 RTU 或 TCP 连接设备，结合报文监视定位通信异常。

教学与协议测试： 用于了解 Modbus 请求、响应和不同数据区域的区别。

有一点需要特别说明：qModMaster 是 Modbus 主站工具，不是从站模拟器。 如果你要模拟一台设备，让自己开发的主站连接并读取虚拟寄存器，需要另外使用 Modbus 从站模拟软件。

五、开源协议与项目状态

qModMaster 使用 Qt 开发，底层通信基于 libmodbus，相关源码就放在仓库的 3rdparty/libmodbus 目录下。仓库支持 Windows 和 Linux，并提供源代码供开发者研究。

需要注意的是，zhanglongqi/qModMaster 仓库目前已是归档只读状态，最后一次代码推送停留在 2017 年 1 月。仓库的最新发布版本标记为 0.4.7。

开源协议方面，仓库的 LICENSE 文件是 GPL-2.0，但 README 中又写着 GPLv3 或更高版本，二者存在不一致。若只是下载使用或研究，建议先阅读随软件提供的许可文件；如果准备修改后分发或集成到商业产品中，应进一步核实实际适用的授权条件及第三方依赖的许可证。

另外，该项目历史较久，使用前最好先确认操作系统、串口驱动和构建环境是否兼容。
